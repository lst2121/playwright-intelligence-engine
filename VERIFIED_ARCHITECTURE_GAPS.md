# Verified Architecture Gaps

**Branch:** `feature/evidence-driven-generation` (branched from `pie-v3.3-frames-drift` @ `b8e7ef2`)  
**Verification Basis:** Direct source inspection + Phase 0 execution baselines (2026-11-12)

---

## 1. Critical P0 Defect: `runGenerationAgent()` Discards `candidate.files`

* **Verified Location:** `src/intelligence/generation-agent.ts` lines 321–374 (`runGenerationAgent`).
* **Exact Call Graph Observed:**
  1. Line 321: Calls `candidate = await author.propose(...)` (`TemplateAuthor`, `HybridAuthor`, or `LlmAuthor`).
  2. Line 333: Evaluates `candidate.files` and `candidate.symbols` via `QualityGate.evaluate(...)`.
  3. Lines 357–369: Constructs `architectureInput` passing only `scenario.steps` and `namePlan: candidate?.symbols`, then calls `const architecture = planArchitecture(architectureInput)`.
  4. Line 372: Writes `architecture` (generated by `planArchitecture()`) via `writeArchitecturePlan(...)`, completely discarding `candidate.files`.
* **Impact:** Even if `LlmAuthor` outputs complete, idiomatic multi-file TypeScript POMs/specs/fixtures, the orchestrator throws away `candidate.files` and overwrites them with single-workflow deterministic templates.

---

## 2. `LlmAuthor` Is a Wrapper Delegating to `HybridAuthor`

* **Verified Location:** `src/authoring/llm-author.ts` lines 4–18 (`LlmAuthor.propose`).
* **Exact Behavior Observed:** `LlmAuthor` unconditionally invokes `this.hybridFallback.propose(input)` and overrides `authorKind: 'llm'`. No multi-file LLM code generation exists yet.
* **Companion Gap in `HybridAuthor` (`src/authoring/hybrid-author.ts`):** Only requests a `NamePlan` JSON from DeepSeek/OpenAI-compatible APIs and delegates file generation to `planArchitecture()`.

---

## 3. Restricted Five-Verb Step Schema in `generation-agent.ts`

* **Verified Location:** `src/intelligence/generation-agent.ts` lines 10–20 (`GeneratedStepSchema`) & lines 121–146 (`generationSystemPrompt`).
* **Exact Behavior Observed:**
  * LLM system prompt forbids raw TypeScript (`"Do not return raw code, patches, or unsupported fields"`) and restricts plans to `click`, `fill`, `navigate`, `assert-visible`, `assert-text` (schema adds `press`, `assert-count`, `assert-value`, still tiny step JSON).
  * User prompt payload sends only `{ input, intelligence }` — zero `AppModel` DOM/locators, zero source code AST/API contracts, zero brownfield fixture exports.

---

## 4. Environment Leakage of `PIE_LLM_API_KEY` into Unit Tests (Fixed in Phase 0)

* **Verified Location:** `src/authoring/hybrid-author.ts` line 15, `src/intelligence/generation-agent.ts` line 198, `tests/unit/generation-agent.test.ts` lines 31, 71, 177.
* **Observed Baseline Failure:** When `PIE_LLM_API_KEY` is present in the developer environment, running `npm test` triggered unmocked HTTPS requests to `https://api.deepseek.com/chat/completions`, causing 3 tests in `tests/unit/generation-agent.test.ts` to fail with `Test timed out in 5000ms` (even the test explicitly titled `uses an explicit deterministic fallback when no LLM provider is configured`).
* **Resolution Applied in Phase 0:** Isolated Vitest unit execution (`!process.env.VITEST || process.env.PIE_LIVE_LLM_TESTS === '1'`) plus explicit `beforeEach`/`afterEach` env hygiene in `generation-agent.test.ts` and deterministic mocked `fetchImpl` test coverage.

## 5. Missing End-to-End Evidence & Planning Stages

1. **No Unified Requirement Intake / Gherkin Round-Trip:** No canonical `workflow-plan.json` or `.feature` export/edit-import validator linking prompts, Markdown/JSON files, `GitDiffCollector`, and application source hints.
2. **Passive Crawl Instead of Stateful Verification:** `AppCrawler` (`src/perception/crawler.ts`) collects static initial DOM elements on routes; it does not execute multi-step workflows, handle interactive login/auth setup cleanly, checkpoint actions, capture before/after DOM diffs, correlate `NetworkCollector` API events, or verify `CLIENT_RELOAD` vs optional read-only `DB` persistence.
3. **No Passive Defect Classification During Exploration:** No `SPEC_VIOLATION | RUNTIME_ERROR | AUTOMATION_GAP | OBSERVED_BEHAVIOR | NOT_VERIFIED` finding tracker that records broken flows as `BLOCKED` without halting healthy workflows or fabricating passes.
4. **Shallow Brownfield Discovery:** `repository-profile.ts` detects directories, locator frequencies, and 2 exemplar snippets, but does not parse `base.extend<T>()` fixture exports, barrel re-exports, auth project dependencies, helper signatures, or POM methods into a `BrownfieldRepositoryGraph`.
5. **Strict `EvidenceBundleSchema` Split:** `src/intelligence/llm-proposal.ts` locks `EvidenceBundleSchema` (`.strict()`) for diagnostic trace repair. Generation requires extending `evidence-bundle.ts` with a dedicated Exploration & Context Bundle without breaking the repair contract.
6. **Transactional `CandidateWriter` Missing:** `writeArchitecturePlan()` (`src/generator/architecture-generator.ts`) is strictly create-only (`SKIP_EXISTING`) with no `MODIFY` semantics, pre-edit file snapshots, rollback, import verification, or protected-file policy.
7. **Three-Stage Generation Verification Loop Missing:** `cli/index.ts` has a prototype single-line text assertion mutation in `architect --verify`, but no integrated Stage 1 target-tsconfig compile + discovery gate, Stage 2 worktree trace-repair loop preserving business assertions, Stage 3 Level C assertion + Level B `page.route()` mutation scoring, or `qa-report.json/.md` generator.

## 6. 12-Item Architecture Review Checklist Answers

1. **Does `generation-agent.ts` discard `candidate.files`?** Yes — verified at lines 321–373.
2. **Can `LlmAuthor` produce complete files independently of `HybridAuthor`?** Not currently — `src/authoring/llm-author.ts` delegates unconditionally to `HybridAuthor`.
3. **Can `evidence-bundle.ts` represent browser, source, and repo evidence without duplication?** Yes, by adding a dedicated generation context bundle alongside `buildEvidenceBundle()` while keeping `EvidenceBundleSchema` strict for repair.
4. **Can Gherkin edits be reliably imported into canonical `workflow-plan.json`?** Not yet — must be built in Phase B with strict tag/scenario-ID/step round-trip validation and stale-plan rejection.
5. **Can the explorer execute multi-step authenticated workflows with checkpoints?** Not yet — `DirectBrowserInvestigator` + `AppCrawler` primitives exist and will be unified in `InteractiveWorkflowRunner` in Phase C.
6. **Are `UI`, `API`, `CLIENT_RELOAD`, and `DB` verification distinguished?** Not yet — explicit enum statuses (`PASS`, `FAIL`, `NOT_VERIFIED`, `NOT_APPLICABLE`) will be added in Phase C.
7. **Can the brownfield scanner discover fixture dependencies and re-exports?** Not yet — will extend `repository-profile.ts` using `ts-morph` in Phase C.
8. **Can `CandidateWriter` handle `CREATE`/`MODIFY` with rollback?** Not yet — `writeArchitecturePlan` is `SKIP_EXISTING`-only; `CandidateWriter` will be implemented in Phase A.
9. **Does the repair loop preserve business assertions?** Yes for repair (`IntentValidator` / `AssertionHasher`); generation repair must explicitly enforce the same invariant when connected in Phase D.
10. **Are mutation tests meaningful and controlled?** Currently only a 1-line `getByText` prototype exists in CLI `--verify`; structured Level C + Level B `page.route()` mutation with valid-mutant denominator tracking will be built in Phase D.
11. **Can the core operate with zero external MCPs?** Yes — Playwright, `ts-morph`, `GitDiffCollector`, `NetworkCollector`, and file/CLI inputs run natively with zero MCP servers.
12. **Does the generation benchmark remain independent of the repair benchmark?** Yes — `benchmarks/runner/master-benchmark-runner.ts` stays dedicated to empirical repair; Phase E will create an independent generation benchmark suite.
