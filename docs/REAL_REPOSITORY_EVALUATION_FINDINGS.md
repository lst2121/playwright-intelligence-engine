## Baseline result from the report

- Primary diagnostic accuracy: 26.1% (6/23).
- Safe abstention: 100% (72/72).
- Determinism: 100%.
- Median latency: 712.4 ms.
- Repair evaluation: not run.

The report correctly exposed a diagnostic-quality problem. It did not show that
PIE was unsafe; it showed that PIE often abstained because it failed to recover
the most useful action and DOM evidence from real Playwright archives.

## Fixes applied after inspecting the real archives

1. Multi-stream archives now prefer the stream containing explicit failure
   events and merge all trace/network streams, preserving both runner action
   errors and browser DOM snapshots.
2. Runner-style `params.locator` and `subtitle` fields are recovered.
3. Parent `test.step` failures inherit child action and call-log evidence.
4. Browser launch command flags are removed before actionability classification,
   preventing false `overlay.*blocking` matches from flags such as
   `--disable-popup-blocking`.
5. `contentFrame()` locator failures are classified as frame-context failures.
6. Playwright trace format v4 has a compatibility adapter, allowing legacy
   Playwright 1.32-era traces to be diagnosed instead of rejected solely on
   format age.
7. DNS transport failures such as `ERR_NAME_NOT_RESOLVED`, `ENOTFOUND`, and
   `DNS_PROBE_FINISHED_NXDOMAIN` are classified as `NETWORK_OFFLINE` and
   safely abstained from repair.

## Targeted post-fix replay

Using the current CLI against the 23 verified primary archive paths produced
10/23 exact expected-category matches (43.5%) in a one-run replay. This is a
diagnostic engineering checkpoint, not a replacement for the official
double-run artifact; the full testbed must be regenerated with the current PIE
build before publishing new benchmark metrics.

The exact-category gains include all four locator-drift mutations, the frame
mutation, the obstruction mutation, and the disabled-control mutation.

## Remaining empirical gaps

- Hydration and delayed-network mutations still resemble locator timeouts
  because the current evidence contract does not yet model readiness timing
  strongly enough. Post-action assertion timeouts now fail closed as
  `HYDRATION_OR_TIMING` rather than being offered as locator repairs.
- Some backend baseline traces have no explicit failed action in the selected
  evidence and require better error-context/HTTP correlation.
- The assertion-vs-authentication case needs ground-truth review because the
  trace contains an actual HTTP 401 signal that correctly takes precedence over
  assertion repair.
- The official report's v4 `UNSUPPORTED_TRACE_FORMAT` labels should be
  recalibrated now that v4 is intentionally supported; unavailable application
  services in those traces should be labeled as environment failures.
- Repair success still requires a separate current-code run through
  `pw-intel repair ... --execute` and its isolated worktree gates.
- The 23-case replay is not yet a release metric; it must be regenerated by
  the testbed owner with the current build and recalibrated ground truth.
- Post-action assertion timeouts in the delayed-hydration and delayed-network
  mutations now classify as `HYDRATION_OR_TIMING` and abstain from repair after
  retaining the inferred `expect` action from the parent test step.
