5.1 The hidden statistical problem
You have 100 test cases, but they are not necessarily 100 independent observations.
For example:
Ten tests might use the same application.
Multiple mutations might target the same DOM component.
All six sites might use the same Chromium version.
Multiple failures might originate from one shared backend.
The same candidate-scoring logic is reused across every case.
These observations are correlated.
This is called clustering.
If the engine succeeds on ten variations of the same checkout button, you have not demonstrated ten independent forms of locator recovery.
You have demonstrated good performance on one family of related cases.
5.2 What does 100% actually mean statistically?
Suppose you observe zero false repairs.
The approximate one-sided 95% upper confidence bound on the underlying failure rate is given by the rule of three:

Allowed operations.
Failure behavior.
Rollback behavior.
