## 1. Executive Summary

In PIE v3.1, repository conventions are treated as **runtime facts**, discovered dynamically via AST inspection and persisted to `.pie/conventions.json` and `.pie/repository-profile.json`, rather than being hardcoded or injected through prompt instructions.

This report documents empirical convention discovery across three real target testbeds:
1. **OWASP Juice Shop** (`d:\Work\pie-real-repository-testbed\disposable-workspaces\juice-shop`)
2. **Twenty CRM** (`d:\Work\pie-real-repository-testbed\disposable-workspaces\twenty\packages\twenty-e2e-testing`)
3. **Logistic Web** (`d:\Work\logistic-web\automation`)

Each repository profile was generated by executing:
```bash
node bin/pw-intel.js profile <workspace-path> --write
```
which invokes `buildRepositoryProfile(root)` and writes `.pie/repository-profile.json` and `.pie/conventions.json`.

## 4. Key Architectural Insights

1. **Policy Over Majority Vote**: In Logistic Web, raw counts show `locator: 100` vs `getByRole: 96`. Rather than defaulting to fragile CSS/XPath locators, the locator engine enforces `preferred: "getByRole"` because role-based locators are prioritized by policy (`prefer-role-over-css`).
2. **Page Object Directory Precision**: In Twenty CRM, the profiler accurately identified `lib/pom` rather than generic `tests/pages`.
3. **Param Property Injection Detection**: The profiler correctly detected Twenty's TypeScript constructor parameter property syntax (`constructor(readonly page: Page)`) vs Logistic Web's explicit assignment syntax (`this.page = page`).
4. **BaseURL Tracing**: BaseURLs are automatically discovered across static strings (`juice-shop: 3000`), environment fallback expressions (`twenty: 3010`), and identifier assignments (`logistic-web: 5173`).
